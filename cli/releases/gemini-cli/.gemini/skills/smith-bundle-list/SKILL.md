# Skill — `/smith-bundle-list`

Lists every bundle available in the Smith CLI catalogue. Read-only ; never
writes.

## Pre-conditions

- `.smith/FUNCTIONAL_SPECIFICATION.MD` must exist (marker that `/smith-init`
  has run on the consumer project). If absent, halt with a one-line message
  telling the user to run `/smith-init` first.

## How to invoke

```
/smith-bundle-list                       # all bundles
/smith-bundle-list --tag build           # bundles tagged "build"
/smith-bundle-list --tag build,frontend  # bundles tagged BOTH "build" AND "frontend"
```

Multiple tags are an **intersection** (AND), not a union.

## What you do

1. Read `cli/bundles/index.yaml`. Parse the `bundles[]` array.
2. If `--tag` is given, filter to bundles whose `tags[]` contains EVERY
   requested tag.
3. Render a markdown table :
   ```
   | Name | Version | Tags | Description |
   |---|---|---|---|
   | mvn | 0.1.0 | build, java, backend | Maven Haiku-offload — … |
   ```
4. End with a one-line summary : `Total: {{N}} bundles`.
5. If no bundle matches the filter, say so explicitly and suggest dropping a
   tag.

## What you do NOT do

- Don't read individual `config.yaml` files — `index.json` is the source of
  truth for listings (regenerated by `/smith-bundle-add`). If the index is
  stale, the user should re-run `/smith-bundle-add` on the affected bundle.
- Don't install anything ; that's `/smith-bundle-install`.
- Don't modify `index.json`.

## Reporting back

The markdown table is the report — print it verbatim.
